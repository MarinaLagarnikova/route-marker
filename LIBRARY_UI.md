# Библиотека маршрутов — экраны подборки, карты и деталей

Дополнение к CLAUDE.md. Соблюдать те же принципы: FSD, shadcn/ui, карта
только через `shared/lib/map-adapter`, mobile-first. Ниже — три экрана
и один общий дровер по макетам (прилагаются как изображения).

## Новое в модели данных маршрута (entities/route или новая entities/library-route)

Маршрут из библиотеки (в отличие от маршрута, загруженного пользователем
вручную) имеет дополнительные поля:

```
{
  id, name, region: { id, name },
  distanceKm, durationLabel ("3–4 дня"),
  difficulty: 'easy' | 'medium' | 'hard',
  elevationGainM,
  type: 'linear' | 'loop' | 'out-and-back', // линейный / кольцевой / радиальный
  nearestSettlement: string,               // "Московская область, г. Лобня"
  description: string,
  source: { name: "Маркированные маршруты России", logoUrl, url },
  track: GeoPoint[],           // полная геометрия для дровера/детального просмотра
  trackSimplified: GeoPoint[], // упрощённая геометрия для мини-превью и общей карты
  checkpoints: Checkpoint[],
}
```

`trackSimplified` обязателен — используется на мини-карте карточки списка
и на карте всей подборки. Полную геометрию `track` там не рисовать по
причинам производительности и читаемости (см. ниже).

## Цвет сложности (зафиксировано макетами, не менять)

- `easy` → зелёный
- `medium` → жёлтый/янтарный
- `hard` → оранжево-красный (тот же акцентный, что и трек на карте)

Везде — кружок-точка слева от слова сложности, как в карточках списка.

## Экран 1 — Страница подборки (`pages/collection` или `pages/region`)

Сверху вниз:

1. Шапка: кнопка «назад» на главную, название региона + счётчик маршрутов
   («Москва и область 27»).
2. Мини-карта региона (не на весь экран): показывает **только маркеры
   стартов маршрутов** этой подборки поверх карты (не полные треки —
   на масштабе всего региона треки нечитаемы и захламляют карту).
   Маркеры — форма «стрелка-компас» как на макете карты подборки
   (не типовая капля-пин). В правом нижнем углу — кнопка разворота
   на весь экран (иконка expand), открывает Экран 2.
3. Список карточек маршрутов. Карточка (переиспользовать компонент
   из уже утверждённой карточки списка):
   - название, дистанция вверху справа с иконкой
   - строка сложности (цветная точка + слово)
   - строка длительности (иконка часов)
   - профиль высоты — тонкая монохромная линия слева
   - мини-превью трека (`trackSimplified`) на подложке настоящей карты
     (не абстрактная иконка) справа, квадратный кроп
   - тап по карточке → открыть Дровер (см. ниже) с этим маршрутом
4. Блок атрибуции внизу списка (не на каждой карточке): логотип
   источника, «Маркированные маршруты России», подпись «Маршруты
   предоставлены», кликабельная стрелка → внешняя ссылка на источник.
   Обязателен для всех маршрутов библиотеки без исключения.

Фильтры/сортировка в макете не показаны — не добавлять, пока не
понадобятся отдельно.

## Экран 2 — Карта с маршрутами подборки (`widgets/collection-map` как fullscreen-оверлей)

- Открывается по кнопке expand с Экрана 1, поверх текущего экрана
  (модальный fullscreen), кнопка × в правом верхнем углу — закрыть
  и вернуться на Экран 1.
- Здесь, в отличие от мини-карты на Экране 1, рисуются **полные треки**
  (`track`, упрощённые до разумного числа точек для производительности —
  см. общий принцип упрощения геометрии в разделе «Продакшн-заметки»),
  каждый — акцентным цветом (оранжево-красный), с маркером-стрелкой
  на точке старта.
- Тап по любому треку или его маркеру-старту → открыть Дровер с этим
  маршрутом, карта остаётся под дровером (не закрывать fullscreen-карту).
- Зум и панорамирование — стандартное поведение карты; при открытии
  сразу `fitBounds` по всем трекам подборки.

## Дровер маршрута (`widgets/route-detail-drawer`)

Общий компонент, переиспользуемый в двух местах — открывается тапом по
карточке в списке (Экран 1) и тапом по треку/маркеру на карте (Экран 2
и в перспективе на будущей общей карте с активным маршрутом). Реализовать
как один компонент, а не дублировать вёрстку.

Поведение: выезжает снизу как bottom sheet (полупрозрачная подложка
затемняет фон, ручка-полоска сверху дровера, кнопка «назад» — закрывает
дровер, не уводит со страницы). Содержимое дровера идентично контенту,
показанному на макете «дровер»:

1. Хлебная крошка мелким текстом — регион («Москва и область»)
2. Название маршрута — крупно
3. Кнопка «+ Добавить на главную» (primary, крупная) + отдельная кнопка
   «избранное» (звезда) рядом — это разные сущности: «избранное» помечает
   конкретный маршрут отдельной пометкой (для показа в подборке
   «Избранное» на главной), «Добавить на главную» — переводит маршрут
   в активные для прохождения. Не путать поведение этих двух кнопок
   при реализации.
4. Параметры списком: Расстояние, Сложность (цветная точка + слово),
   Время, Перепад высот, Ближайший населённый пункт (если указан
   в данных маршрута — можно отсутствовать не у всех).
5. Карта маршрута — полная геометрия, маркер-стрелка на старте.
6. Заголовок «Описание» + текст описания маршрута.
7. Блок атрибуции источника (тот же формат, что на Экране 1) —
   обязателен.

## Обновления главного экрана (`pages/start`)

Судя по макету, состав главной меняется:

- Активный маршрут (в процессе прохождения) — карточка сверху с текущим
  прогрессом, как раньше.
- Раздел «Завершённые N» — сворачиваемый, при разворачивании показывает
  список завершённых маршрутов с датой и итоговым временем прохождения.
- Раздел «Подборки маршрутов N» (N — общее число маршрутов во всех
  подборках) — горизontal-скролл карточек регионов, «Избранное» всегда
  первой карточкой.
- Кнопка «Загрузить GPX трек» остаётся внизу как раньше — вход для
  маршрута не из библиотеки.

**Требует answера перед реализацией:** что именно происходит при
«Добавить на главную», если на главной уже есть один активный
маршрут — становится ли главная экраном с несколькими одновременными
активными маршрутами (список вместо одной карточки), или новый маршрут
просто заменяет текущий активный? Макеты показывают только один активный
маршрут единовременно — уточнить у продакт-оунера перед стартом
разработки этой части, не додумывать самостоятельно.

## Продакшн-заметки (важно, не пропустить)

- Профиль высоты на карточках и в дровере должен строиться по реальным
  данным высоты из GPX (`elevation` каждой точки трека), а не быть
  декоративной волной — переиспользовать логику построения профиля
  из самого первого прототипа приложения (min/max высота, путь по
  накопленному километражу).
- `trackSimplified` — обязательное поле, генерируется на этапе
  наполнения библиотеки (или на лету с кэшированием), не на клиенте
  при каждом рендере карточки — иначе список из 27+ маршрутов будет
  тормозить при открытии страницы подборки.
- Маркер-стрелка (не капля-пин) — переиспользовать одну иконку/компонент
  маркера везде, где на карте показывается старт маршрута библиотеки.
